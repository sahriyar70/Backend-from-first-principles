## এরর হ্যান্ডলিং এবং ফল্ট-টলারেন্ট ব্যাকএন্ড সিস্টেম তৈরি করার নির্দেশিকা

ব্যাকএন্ড ইঞ্জিনিয়ারিংয়ে রিয়েল-টাইম প্রডাকশন এনভায়রনমেন্টে কীভাবে এরর শনাক্ত করা, প্রিভেন্ট বা প্রতিরোধ করা, রিকভার করা এবং সঠিকভাবে হ্যান্ডেল করা যায় তার একটি সুসংগঠিত নির্দেশিকা।

---

##  Core Philosophy / মূল মানসিকতা

ব্যাকএন্ড ডেভেলপমেন্টে এরর বা ভুল হওয়া একটি স্বাভাবিক বিষয়। ডাটাবেস কোয়েরি ফেইল হওয়া, এপিআই টাইম-আউট হওয়া, বা ইউজার ভুল ডাটা পাঠানো খুবই সাধারণ ঘটনা।

> **মূল নিয়ম (Key Rule):** সেরা এরর হ্যান্ডলিং সিস্টেম সেটিই, যা এরর ঘটার আগেই সেটিকে প্রতিরোধ করার প্রস্তুতি রাখে। ব্যাকএন্ড ইঞ্জিনিয়ার হিসেবে সিস্টেমকে এমনভাবে ডিজাইন করতে হবে যেন কোনো অংশ ডাউন হলেও পুরো অ্যাপ ক্র্যাশ না করে (Graceful Degradation)।

##  1. Taxonomy of Backend Errors / এররের ধরনসমূহ

### 1. Logic Errors (লজিক এরর)
* **বিবরণ:** এগুলো সবচেয়ে বিপজ্জনক এরর। কোড ক্র্যাশ করে না কিন্তু ভুল আউটপুট বা ফলাফল দেয়।
* **প্রভাব:** নীরবে ডাটা নষ্ট করে বা ব্যবসার ক্ষতি করে (যেমন: ই-কমার্স সাইটে দুবার ডিসকাউন্ট অ্যাপ্লাই হয়ে যাওয়া)।
* **কারণ:** রিকোয়ারমেন্ট ভুল বোঝা, জটিল অ্যালগরিদমের এজ-কেস (Edge cases) মিস করা।

### 2. Database Errors (ডাটাবেস এরর)
* **Connection Failures:** নেটওয়ার্ক সমস্যা বা ডাটাবেস কানেকশন পুল (Connection Pool) ফুল হয়ে যাওয়া।
* **Constraint Violations:** ইউনিক কি (Unique Key) ভায়োলেশন বা ফোরেন কি (Foreign Key) মিসিং থাকা।
* **Query & Deadlock Errors:** ভুল SQL কোয়েরি, কোয়েরি টাইম-আউট বা একাধিক প্রসেসের মধ্যে ডেডলক হওয়া।

### 3. External Service Errors (এক্সটার্নাল সার্ভিস এরর)
* **ডিপেনডেন্সি:** থার্ড-পার্টি সার্ভিস যেমন পেমেন্ট গেটওয়ে, অথেনটিকেশন (Auth0/Clerk), ইমেইল সার্ভিস বা S3 স্টোরেজ।
* **সমস্যা:** সার্ভিস ডাউন হওয়া, নেটওয়ার্ক টাইম-আউট, বা অতিরিক্ত রিকোয়েস্ট পাঠানোর কারণে **Rate Limiting (`HTTP 429`)** এরর খাওয়া।

### 4. Input Validation Errors (ইনপুট ভ্যালিডেশন এরর)
* **প্রথম সুরক্ষা স্তর:** ক্লায়েন্ট বা ইউজারের কাছ থেকে আসা ডাটা সিস্টেমে ঢোকার আগেই চেক করা।
* **চেকসমূহ:** ডাটার ফরম্যাট (ইমেইল, তারিখ), রেঞ্জ (সর্বনিম্ন ও সর্বোচ্চ সাইজ), এবং আবশ্যক ফেইল্ডসমূহ (Required fields)।

### 5. Configuration Errors (কনফিগারেশন এরর)
* **এনভায়রনমেন্ট ড্রিপ্ট:** Development, Staging এবং Production এনভায়রনমেন্টের মধ্যে `.env` ফাইলের তথ্যে অমিল থাকা।
* **Best Practice:** অ্যাপ্লিকেশন চালু হওয়ার সময়ই (Startup Phase) প্রয়োজনীয় এনভায়রনমেন্ট ভেরিয়েবল চেক করে নেওয়া। অনুপস্থিত থাকলে সার্ভার স্টার্ট না করে Fail Early করা ভালো।

##  2. Proactive Error Detection & Observability / এরর শনাক্তকরণ ও মনিটরিং

[ Incoming Request ] ──► [ Validation Boundary ] ──► [ Core Logic / DB ]
│
(Health Checks & Logs)
│
▼
[ Monitoring / Dashboard ]

### Health Checks (হেলথ চেক)
* **Basic Endpoint:** একটি সাধারণ `/health` এপিআই রাখা যা শুধুমাত্র 서버 চালু আছে কি না (200 OK) তা রিটার্ন করে।
* **Deep Health Checks:** ডাটাবেস, রেডিস ক্যাশ এবং বাহ্যিক সার্ভিসগুলোর সাথে কানেকশন ঠিক আছে কি না তা টেস্ট কোয়েরির মাধ্যমে নিশ্চিত হওয়া।

### Monitoring & Logging (মনিটরিং ও লগিং)
* **পারফর্মেন্স ট্র্যাক:** রেসপন্স টাইম হঠাৎ বেড়ে যাওয়া বা সফল ট্রানজ্যাকশন হঠাৎ কমে যাওয়া দেখে সম্ভাব্য এরর অনুমান করা।
* **Structured Logging:** এলোমেলো টেক্সটের বদলে structured `JSON` ফরম্যাটে লগ রাখা এবং Correlation ID ব্যবহার করে লগ ট্র্যাকিং করা (যেমন: Grafana Loki বা ELK stack দিয়ে)।

##  3. Error Recovery & Propagation Strategies / এরর থেকে পুনরুদ্ধারের উপায়

| এররের ধরন | কৌশল (Strategy) | প্রয়োগের নিয়ম (Implementation) |
| :--- | :--- | :--- |
| **Recoverable (পুনরুদ্ধারযোগ্য)** | Retry Mechanism | Rate Limit বা সাময়িক নেটওয়ার্ক ডাউন থাকলে **Exponential Backoff** সহ রিট্রাই করা |
| **Non-Recoverable (অপুনরুদ্ধারযোগ্য)** | Graceful Degradation | ব্যাকআপ ক্যাশ ডাটা দেখানো, সার্কিট ব্রেকার প্যাটার্ন বা নন-এসেনশিয়াল ফিচার অফ করে দেওয়া |
| **Cascade Control** | Isolation & Queues | বার্তা আদান-প্রদানে RabbitMQ/Kafka এর মতো মেসেজ কিউ (Message Queue) ব্যবহার করা |

##  4. Global Error Handling Strategy / গ্লোবাল এরর হ্যান্ডলিং

সিস্টেমের প্রতিটি ফাংশনে আলাদা আলাদাভাবে এরর হ্যান্ডেল না করে একটি **Global Error Handler Middleware** এর মাধ্যমে সেন্ট্রালাইজড বা কেন্দ্রীয়ভাবে হ্যান্ডেল করা ভালো।

### আর্কিটেকচার লেয়ারিং
`Routing` ──► `Handler (Validation)` ──► `Service (Orchestrator)` ──► `Repository (DB/Queries)`

### গ্লোবাল মিডলওয়্যারের সুবিধাসমূহ
1. **কনসিস্টেন্সি (Consistency):** পুরো অ্যাপ্লিকেশনে স্ট্যান্ডার্ড HTTP স্ট্যাটাস কোড (`400`, `404`, `500`) এবং একই ধরনের JSON এরর ফরম্যাট বজায় থাকে।
2. **DRY Principle:** প্রতিটা কন্ট্রোলার বা সার্ভিসে বারবার `try-catch` লেখার দরকার হয় না।
3. **Safety Net:** কোনো অপ্রত্যাশিত এরর কোডে হ্যান্ডেল না করা থাকলেও গ্লোবাল মিডলওয়্যার তা নিরাপদে ক্যাপচার করে নেয়।

```json
// উদাহরণ: স্ট্যান্ডার্ড এরর রেসপন্স ফরম্যাট
{
  "code": 400,
  "message": "Resource validation failed",
  "errors": [
    {
      "field": "email",
      "message": "Email address already exists"
    }
  ]
}
